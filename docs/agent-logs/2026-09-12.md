## Session Entry 4 — Depositphotos Full-String Native Comma Splitting and Chip Overwrite Elimination

**Time:** ~04:10 WIB<br>
**Branch:** `task/platform-adapters`<br>
**Commit:** `fix(depositphotos): inject full comma string for native multi-chip splitting and prevent chip overwrite`<br>
**Product code changed:** YES<br>
**Pushed:** NO

### What Was Done
- **Root Cause Analysis of Single Tag Chip Bug:**
  - In Session Entry 3, testing confirmed cross-card leakage was eliminated (Card 1 and Card 2 received their own separate descriptions and keywords). However, each card only retained the very last keyword (e.g. Card 1 had only `[pet training x]`, Card 2 had only `[texture x]`, counter at 49).
  - Identified fatal selector collision: the fallback loop queried `'span.tagseditor__item_new span.tagseditor__tag, div.tagseditor span[contenteditable="true"]'`. Because every committed chip on Depositphotos also contains `span.tagseditor__tag[contenteditable="true"]`, and committed chips appear prior to the new input in DOM order, `querySelector` repeatedly matched the first committed chip on iterations 2 through 50, overwriting the same chip with each subsequent keyword.
- **Depositphotos Native Multi-Chip Splitting (`unfinished.js`):**
  - Reverse-engineered `DP.Collection.Tags` in `unfinished.js`. Found `splitModelByKeywordNameRegex: /[,;]/g` and `_splitKeywordName()`.
  - When `keydown Enter` (keyCode 13) or `blur` is fired on `span.tagseditor__item_new`, Depositphotos reads `item.value()` (`this.$tag().text()`) and passes it to `this.collection.add(model)`.
  - If the value contains commas (e.g., `"dog, puppy, cute, animal"`), `_updateModel()` and `_addSplittedKeywords()` natively split the string into individual models and render all separate chips simultaneously in a single transaction.
- **Full-String Direct Injection (`src/adapters/DepositphotosAdapter.js`):**
  - Updated `fillMetadata()`:
    1. Primary Strategy: Injects the entire comma-separated string (`cleanTagsString`) directly into `activeInput` (`span.tagseditor__item_new span.tagseditor__tag`) and fires `simulateEnterKey(activeInput)` (and bubbles to `itemParent`). Depositphotos natively splits all 50 keywords into chips in ~250ms.
    2. Verification & Guard: Counts `createdChips = root.querySelectorAll('span.tagseditor__item:not(.tagseditor__item_new)')`.
    3. Sequential Fallback with Strict Selector: If fewer chips than expected were created, safely cleans up any raw comma chip and enters tags sequentially using ONLY `span.tagseditor__item_new span.tagseditor__tag, span.tagseditor__item[data-type="input"] span.tagseditor__tag`, completely eliminating `div.tagseditor span[contenteditable="true"]` to guarantee existing chips are never overwritten.
- **Unit & Regression Verification:**
  - `scratch/test_depositphotos_fixes.mjs`: 33/33 assertions passed.
  - `scratch/test_tier3_adapters.mjs`: 105/105 assertions passed.
  - Zero Native Emoji policy strictly enforced.

- **Depositphotos Engine Reverse-Engineering (`unfinished.js`):**
  - Analyzed Depositphotos' native Backbone view (`className: 'tagseditor'`) to determine exact tag creation mechanics:
    1. It delegates `'paste ._tagseditor__item, .paste_editor__tag'`, extracting text via `e.originalEvent.clipboardData.getData('text')` and executing `_trimData()` and `_userCompleteItem(params)`.
    2. It delegates `'keydown ._tagseditor__item'`, intercepting `Enter` (code 13) and `Comma` (code 188) to commit `span.tagseditor__tag` into a permanent `_tagseditor__item` chip.
    3. It does NOT listen to `InputEvent('input')` for tag creation, explaining why setting `textContent` without firing `paste` or `keydown Enter` resulted in raw text overlapping the "Keywords" label instead of converting into chips.
- **Dual-Strategy Keyword Injection (`src/adapters/DepositphotosAdapter.js`):**
  - **Primary Strategy (Native Full-String Paste)**: Dispatches synthetic `ClipboardEvent('paste')` with `DataTransfer` carrying the full comma-separated keyword string (`cleanTagsString`) directly on `span.paste_editor__tag` / `div.tagseditor` inside the active card.
  - **Fallback Strategy (Sequential Enter Loop)**: If browser isolated-world restrictions strip `clipboardData`, instantly executes a rapid loop per keyword setting text into `span.tagseditor__item_new > span.tagseditor__tag` and dispatching `simulateEnterKey`, perfectly matching the user's manual interaction recording (`rekaman-platform-20260912_034231-v2.json`).
- **Namerow Defocusing Alignment (`src/adapters/DepositphotosAdapter.js`):**
  - Clicks `div.itemeditor__row.itemeditor__namerow span.itemeditor__name` to defocus after description injection and after keyword injection.
