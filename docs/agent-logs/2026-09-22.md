### What Was Done
- **Diagnosis of Google Gemini Provider Error 400**:
  - Analyzed console logs (`bahan/log_console_shutterstock.md` and `bahan/log_console_adobestock.md`) where calls to Gemini failed with: `Provider API error (400): [{"error": {"code": 400, "message": "Missing or invalid Authorization header.", "status": "INVALID_ARGUMENT"}}]`.
  - Identified root cause in `src/background/service_worker.js:buildProviderRequestParams`: while Google Gemini base URL is configured as OpenAI-compatible (`https://generativelanguage.googleapis.com/v1beta/openai/`), the `if (isGemini)` branch only attached `?key=` query param and `x-goog-api-key` header, omitting `Authorization: Bearer <API_KEY>`.
  - Verified that Google's `/v1beta/openai/chat/completions` endpoint strictly validates standard OpenAI authentication headers and rejects calls missing `Authorization: Bearer ...`.
  - Contrasted with `fetchProviderModels` (which already included both headers and succeeded) and OpenRouter (which succeeded because it executed the `isOpenRouter` branch).
- **Service Worker Authorization Fix (`src/background/service_worker.js`)**:
  - Added `headers['Authorization'] = `Bearer ${activeKey}`;` to the `if (isGemini)` block in `buildProviderRequestParams`.
  - Verified syntax via `node --check src/background/service_worker.js`.
