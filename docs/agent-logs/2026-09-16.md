### What Was Done
- **Cross-Page Navigation Continuation for Dreamstime (`src/background/service_worker.js`, `src/overlay/AutomationOrchestrator.js`, `src/overlay/overlay.js`)**:
  - Identified root cause of automation stoppage on Dreamstime: Unlike SPA microstocks, Dreamstime performs a full-page navigation / reload to the next asset URL (`/upload/edit?item_id=...`) upon saving or submitting an asset. The background worker's `tabs.onUpdated` auto-heal previously caught this page reload as a tab reset and wiped `rj_automation_state` to idle. Concurrently, `restoreAutomationState()` in newly mounted `OverlayHUD` instances wiped storage because `orchestrator.isProcessing` was initially false on a fresh JS context.
  - In `service_worker.js:tabs.onUpdated`: added an explicit exception for Dreamstime cross-page continuation (`state.platformId === 'dreamstime' && !state.isStopping && (url === '' || url.includes('dreamstime.com'))`) preventing `resetAutomationState()` from wiping the active batch.
  - In `AutomationOrchestrator.js`:
    - Added `this.isExecutionLoopActive` boolean to decouple the visual HUD running state from active loop iteration.
    - Updated `start(initialCount = 0)` to support cross-page batch progression using `processedCount`.
    - Persisted `processedCount` into `_setAutomationState` on each asset completion.
    - Added `beforeunload` window listener guard to protect persistent storage from being reset to idle during page teardown.
    - Handled zero detected assets on post-submission batch landing page (`Finished ${initialCount} assets`).
  - In `overlay.js:restoreAutomationState()`:
    - Added check for active Dreamstime continuation (`isDreamstimeContinuation`).
    - Maintains the "Stop" button and running badge UI immediately upon page mount, preventing visual flicker.
    - Schedules `startAutomation(state.processedCount || 0)` with a 1000ms delay to let the newly loaded asset DOM settle before resuming automation.
- **Stop Button Label Shortening across Popup & HUD (`src/popup/popup.js`, `src/overlay/overlay.js`)**:
  - Shortened active running button label from `"Stop Automation"` to simply `"Stop"` in both Popup (`popup.js:967`) and Floating Overlay HUD (`overlay.js:1079`).
  - Updated tooltips to `"Stop"`.
  - Maintained crisp 12px font-weight 500 typography and square stop Lucide SVG icon (`<rect ...>`).
- **Support / Donation Icon Outline Box Removal (`src/popup/popup.html`, `src/popup/popup.css`, `src/overlay/overlay.css`)**:
  - Diagnosed root cause: `popup.html` applied `.rj-btn-icon` to `#supportProgressIcon`, inheriting a 34x34px bordered input action container from `components.css:527` that clashed with the button's background.
  - Removed `.rj-btn-icon` class from `#supportProgressIcon` in `popup.html`.
  - Added dedicated transparent rules (`display: inline-flex; align-items: center; justify-content: center; background: transparent !important; border: none !important; box-shadow: none !important; padding: 0; margin: 0;`) in both `popup.css` and `overlay.css`.
