### What Was Done
- **Mode B Navigation Decoupling (`src/overlay/AutomationOrchestrator.js`)**:
  - Investigated issue reported by user where Mode B ("Submit Immediately") ceased progressing after the first asset and falsely marked automation as completed / finished.
  - Identified root cause: In Dreamstime, clicking `#submitbutton` automatically submits the file and advances the editor modal to the next unfinished asset (or closes the modal if the queue is empty). The orchestrator previously executed `adapter.saveDraft()`, followed by `adapter.submitForReview()`, and then unconditionally executed `adapter.navigateToNext()`.
  - When `navigateToNext()` was called in Mode B, it read the newly loaded asset ID, added it to `processedAssetIds`, and clicked the next arrow a second time—skipping assets or tripping the Infinite Carousel Guard (`processedAssetIds.has(nextId) === true`), terminating the loop after 1 asset.
  - Decoupled Mode A vs Mode B navigation in `AutomationOrchestrator.js`: Mode B now delegates post-submission progression to `adapter.handlePostSubmitTransition(currentId)` while Mode A retains standard carousel navigation via `adapter.navigateToNext()`.
- **Dreamstime Post-Submit Auto-Transition Handler (`src/adapters/DreamstimeAdapter.js`)**:
  - Implemented `handlePostSubmitTransition(submittedAssetId)`:
    - Registers `submittedAssetId` into `this.processedAssetIds`.
    - Checks if the edit modal closed immediately upon submission (`!modalActive`), cleanly returning `{ done: true, nextAssetId: null }` when all assets in the batch are finished.
    - Polls up to 5000ms for the modal to display the next asset ID (`candId && candId !== submittedAssetId`).
    - Provides fallback next-arrow clicking only if Dreamstime auto-advance does not trigger within the timeout period.
    - Returns `{ done: false, nextAssetId }` when the next asset is ready, allowing the orchestrator loop to seamlessly proceed to the next item.
- **Save and Submit Toast Race Condition Resolution (`src/adapters/DreamstimeAdapter.js`)**:
  - Investigated race condition where `submitForReview()` immediately caught lingering `.noty_bar` DOM nodes from the preceding `saveDraft()`, exiting immediately before server submission confirmation.
  - Updated `saveDraft()` to purge lingering `.noty_bar` elements once the close animation completes.
  - Added pre-submit cleanup in `submitForReview()` to clear stale `.noty_bar` elements before clicking the submit button, ensuring the toast watcher only detects the newly spawned submit notification.
