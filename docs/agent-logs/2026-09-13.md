### What Was Done
- **Root Cause Diagnosis of Reported Live Issues:**
  1. *Dropdown 3x Open/Close Loop*:
     - In `_setSpectrumOrNativeDropdown`, an aggressive 3-attempt loop clicked the dropdown button, waited 250ms, and performed an immediate `document.querySelector`.
     - Because React Spectrum renders options via animated portal overlays (`div.spectrum-Menu`), the element was not immediately queryable at 250ms. The loop concluded the element was missing, clicked the button to close it, and repeated 3 times.
     - Furthermore, unlike the reference extension (`C:\Users\admin\Desktop\git\RJ_AdobeStock_Auto\scripts\content.js`), it failed to check if the field was already set to the target value before touching the UI.
  2. *Popup & Storage Permanently Stuck on "Stopping..."*:
     - Clicking "Stop" sets `rj_automation_state: { isRunning: true, isStopping: true, status: 'stopping' }` in `chrome.storage.local`.
     - When the user refreshed the active tab mid-stop, Chromium terminated the page's JavaScript execution context before the orchestrator's completion block could reset state to `idle`.
     - Reloading the extension in `chrome://extensions` reloads the service worker but leaves `chrome.storage.local` untouched.
     - `popup.js` and `overlay.js` blindly loaded this stale stopping state on launch, set `btnToggleAutomation.disabled = true`, locked all form inputs, and remained frozen indefinitely.
- **Architectural Implementation:**
  1. *Adobe Stock Direct Select Injection as Primary Strategy (`src/adapters/AdobeStockAdapter.js`)*:
     - **Fast-Path Verification**: Checks if `nativeSelect && String(nativeSelect.value) === stringTargetKey`. If already set, returns `true` immediately without opening the dropdown button.
     - **Direct Select Injection (Primary Strategy)**: Prioritized direct injection to `nativeSelect` via `setNativeValue`, `change`, and `input` events before touching the UI. When confirmed, returns immediately (0 button clicks, zero UI flicker, immune to 150% page zoom or popover clipping).
     - **Fallback Spectrum Button Dropdown**: If native select is absent or unconfirmed, expands the button once, awaits `waitForElement(optionSelectors, document, 3000)`, centers scrollbar on the option if listbox has overflow, and clicks the target option.
  2. *Enhanced Native Value Setter (`src/adapters/utils/dom_helpers.js`)*:
     - Extended `setNativeValue` to explicitly check `HTMLSelectElement.prototype.value` descriptor when `element instanceof HTMLSelectElement`, bypassing framework overrides on native selects.
  3. *Multi-Layer Auto-Healing Engine for Automation State*:
     - **Layer 1 (`src/background/service_worker.js`)**: Added `resetAutomationState()`. Clears stale state on `chrome.runtime.onInstalled`, `chrome.runtime.onStartup`, and when an active tab reloads (`chrome.tabs.onUpdated` status `'loading'`). Added `'RESET_AUTOMATION_STATE'` runtime message handler.
     - **Layer 2 (`src/content/content_main.js`)**: Enhanced `PING_HUD` response to return live `isAutomationRunning` and `isStopping` flags from `OverlayHUD`.
     - **Layer 3 (`src/overlay/overlay.js`)**: In `restoreAutomationState()`, immediately auto-heals storage to `{ isRunning: false, isStopping: false, status: 'idle' }` if a newly mounted overlay detects leftover `isStopping` or dead `isRunning` state on page reload.
     - **Layer 4 (`src/popup/popup.js`)**:
       - On `DOMContentLoaded`, pings the active tab when reading an active/stopping storage state. If the tab is missing, closed, dead, or not actually running, executes `autoHealAutomationState()`: sets storage to `idle`, unlocks all inputs, and renders "Start Automation".
       - In `btnToggleAutomation` click listener, allows clicking while `isStopping` to force-reset to idle.

### What Was Done
- **Root Cause Diagnosis of Adobe Stock Dropdown Selection Glitch:**
  - In user live testing on Adobe Stock (`contributor.stock.adobe.com/en/uploads`) with page zoom at 110%, selecting Korean language resulted in "Polski" (Polish) being selected instead of Korean, with the dropdown glitching and repeating.
  - Analysis of recording `rekaman-adobestock-20260913_214721-v2.json`, console log `log_console_adobestock.md`, and DOM structures revealed two primary flaws:
    1. *Fatal altKeys & Array Traversal Bug*: In `AdobeStockAdapter.js`, `altKeys` was set to `['14', '10']` for Korean. In Adobe Stock's DOM, ID `14` is Korean while ID `10` is Polish (Polski). When searching native `<select name="language">`, option 8 (value `10`, Polski) matched before option 9 (value `14`, Korean), causing the form's native select to be erroneously set to Polski.
    2. *Dropdown Container Clipping & Scrollbar Inaction*: Dropdown options are housed within `div.spectrum-Menu[role="listbox"]` with `overflow: hidden auto`. At 110% zoom, the bottom item (`한국`, option 14) is partially clipped. Calling `scrollIntoView({ block: 'nearest' })` did not scroll the listbox container.
    3. *Pointer Event Discard in React Aria*: `simulateClick` dispatched synthetic events without `clientX`/`clientY` (defaulting to `0, 0`) and with `buttons: 1` on `pointerup`. React Aria (`usePress`) verified `elementFromPoint(0, 0)` which fell outside the option, canceling the click event.
- **Architectural Refactoring (Strict Numeric ID Targeting & Active Scrollbar Centering):**
  - **Eliminated UI Label Matching**: Per architectural guidance, completely removed text/label matching (`btnText.includes(targetText)`, `opt.text === targetText`) to ensure immunity against translated contributor pages and browser locale variations.
  - **Corrected `ADOBE_LANGUAGE_MAP`**: Fixed swapped language IDs (German is `'4'`, French is `'2'`), mapped Korean strictly to `'14'`, and removed rogue alternate keys.
  - **Enhanced `_setSpectrumOrNativeDropdown` in `src/adapters/AdobeStockAdapter.js`**:
    - *Step 1*: Matches native `<select>` options strictly by `opt.value === stringTargetKey`.
    - *Step 2*: Opens Spectrum dropdown via trigger button (`aria-expanded="true"`).
    - *Step 3*: Identifies scrollable container `listbox = document.querySelector('div[role="listbox"], .spectrum-Menu')`. If `listbox.scrollHeight > listbox.clientHeight`, dynamically scans and adjusts `listbox.scrollTop = optionEl.offsetTop - (listbox.clientHeight / 2) + (optionEl.offsetHeight / 2)` and calls `optionEl.scrollIntoView({ block: 'center', behavior: 'instant' })`.
    - *Step 4*: Targets inner label/grid if present, dispatches pointer events with center coordinates and `buttons: 0` on release, and provides `simulateEnterKey(optionEl)` keyboard navigation fallback.
  - **Enhanced `simulateClick` in `src/adapters/utils/dom_helpers.js`**:
    - Calculates element center coordinates via `element.getBoundingClientRect()` and passes realistic `clientX`, `clientY`, `screenX`, `screenY`.
    - Ensures `buttons: 0` on `pointerup` and `mouseup` to adhere to pointer interaction specifications.
  - **Universal Benefit for Category Dropdown**:
    - Category selection shares `_setSpectrumOrNativeDropdown`, guaranteeing that bottom categories (e.g. *Travel* `10988`) also center smoothly and click reliably without clipping or locale dependencies.
