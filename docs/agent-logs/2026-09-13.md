## Session Entry 2 — MiriCanvas Dual-Strategy Keyword Chip Clearing with Per-Chip Remove Icon Fallback and Sequential Form Ordering

**Time:** ~00:50 WIB<br>
**Branch:** `task/platform-adapters`<br>
**Commit:** `fix(miricanvas): implement dual-strategy keyword chip clearing with per-chip remove icon fallback`<br>
**Product code changed:** YES<br>
**Pushed:** NO

### What Was Done
- **Root Cause Analysis of Keyword Chip Accumulation (29/25 and 26/25 chips):**
  - Console logs (`bahan/log_console_miri.md`) showed that on Asset 1 (`Clearing 4 pre-existing keywords...`), the editor ended up with `Verified: 29 keyword chips active in editor` (4 old + 25 new). On subsequent assets, 1 old chip remained, resulting in 26 chips (1 old + 25 new).
  - Reverse engineering and DOM analysis revealed:
    1. Base UI's trash button `<button data-base-ui-tooltip-trigger="" data-f="TT-c273">` contains `<div data-f="DD-04b4"><svg data-f="DD-e725"><path d="M17 6..."></path></svg></div>`.
    2. Calling `trashBtn.click()` in a content script without triggering pointer/mouse events on the innermost icon element and without bubbling synthetic `click` MouseEvents caused React 18 / Base UI event handlers not to process the bulk deletion in the live browser.
    3. Furthermore, when `clearMetadata()` was run at the very beginning of `fillMetadata()`, subsequent UI updates (AI generator toggle, Pricing tier radio clicks) re-rendered the form and occasionally restored or decoupled chip state.
- **Implementation in `src/adapters/MiriCanvasAdapter.js`:**
  - `_findTrashButton(container)`:
    - Updated direct match to locate `div[data-f="DD-04b4"], svg[data-f="DD-e725"]` and traverse up parent elements to find the enclosing `<button>`, compatible with both real browser DOM and mock environments.
  - `clearTitle()`:
    - Dispatches pointer and click events on both the inner icon element and the button itself.
  - `clearKeywords()` (Dual-Strategy Architecture):
    - **Strategy 1 (Primary Bulk Deletion):** Dispatches full pointer and bubbling `MouseEvent('click')` events to both the inner icon (`div[data-f="DD-04b4"]` / `svg[data-f="DD-e725"]`) and the `<button>`. Actively polls up to 800ms for chips to reach 0. If 0 chips remain, returns immediately.
    - **Strategy 2 (Resilient Per-Chip Removal Fallback):** If chips remain in DOM (`chipsLeft.length > 0`), falls back to iterating over each remaining chip (`span[data-f="CL-67aa"]`), locating its specific remove icon (`svg[data-f="CD-213b"]` or `path[d*="10.587"]`), and clicking it with a 50ms safe delay between clicks to allow React 18's state reconciler to unmount each chip cleanly without state collision.
  - `fillMetadata()`:
    - Restructured execution order to match the exact user flow:
      1. AI image generator checkbox toggle.
      2. Content Tier (Standard vs Premium) radio selection.
      3. Content type radio selection.
      4. `clearTitle()` immediately before Title injection.
      5. `clearKeywords()` immediately before Keywords injection.

### What Was Done
- **Root Cause Analysis of Keyword Chip Conversion Failure & Trash Button Target:**
  - In user's live testing and latest interaction log, keyword strings were entered into the input box (`input.panda-eNrFAg` / `div[data-f="SD-e7b2"] input`) but failed to convert into interactive chips (`span[data-f="CL-67aa"]`).
  - Analysis of recording `dev-tools/recordings/rekaman-miri-20260913_000957-v2.json` and Base UI behavior identified two primary causes:
    1. Setting input value via standard `setNativeValue()` dispatched an immediate `blur`, causing the input to lose focus before Enter key events could trigger the internal chip parsing lifecycle.
    2. Premature clearing of input text wiped the uncommitted tokens before React 18 / Base UI finished parsing the batch into individual chips.
    3. In header action containers (`div[data-f="IA-61ae"]` for keywords, `div[data-f="FA-93a1"]` for title), two buttons exist: `buttons[0]` is Copy (`div[data-f="CD-7f75"]`) and `buttons[1]` is Trash (`div[data-f="DD-04b4"]`). Previous selector logic occasionally fell back to `buttons[0]`, invoking copy actions instead of deletion.
- **Implementation in `src/adapters/MiriCanvasAdapter.js`:**
  - `_findTrashButton(container)`:
    - Direct match targeting `button:has(div[data-f="DD-04b4"]), button:has(svg[data-f="DD-e725"])`.
    - Explicitly filters out copy buttons containing `CD-7f75` or `ID-430b`.
    - If multiple buttons are present, selects `buttons[1]` (the trash button in MiriCanvas DOM), preventing copy actions.
  - `clearKeywords()`:
    - Clicks the verified trash button.
    - Extended polling verification up to 1200ms (12 attempts) for chip clearance.
  - Keyword Injection in `fillMetadata()`:
    - Invokes native `HTMLInputElement.prototype.value` setter without firing premature blur.
    - Dispatches synthetic `InputEvent` with `inputType: 'insertFromPaste'` and `data: tagBatchString`.
    - Dispatches full Enter key sequence (`keydown` -> `change` -> `keyup`) with `keyCode: 13`.
    - Implemented active polling (up to 1200ms) waiting for `span[data-f="CL-67aa"]` chip count > 0.
    - Fallback 1: Dispatches Comma key (`keyCode: 188`) followed by Enter retry if chips are not yet formed.
    - Fallback 2: Sequential per-tag injection with comma and Enter if batch parsing fails.
    - Added DOM chip verification logging confirming the exact active chip count.
    - Cleans up leftover uncommitted text only after chip verification completes.
    - Safely constructed `KeyboardEvent` / `Event` options in `dispatchKeyEvent` avoiding assignments to read-only getters.
  - Resilient Bulk Save Lifecycle in `bulkSave()`:
    - Clicks Save Metadata button `button[data-f="SG-8f01"]`.
    - Actively polls (up to 8000ms) for button disabled state (`saveBtn.disabled || saveBtn.hasAttribute('disabled') || saveBtn.getAttribute('aria-disabled') === 'true'`) or toast notification (`section[data-f="SL-2fb0"]`).
    - Adds a mandatory 2000ms buffer for background synchronization / network persistence.
    - Re-queries the navbar Select All checkbox (`nav[data-f="CT-a2b2"] input[data-f="CI-66e5"]`) fresh to prevent stale element references, and unchecks it cleanly.
